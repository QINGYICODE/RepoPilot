# 公开仓库接入验证

日期：2026-11-04。本机 MySQL `localhost:3306/repopilot`，不使用 Docker。真实目标为用户指定的 [QINGYICODE/RepoPilot](https://github.com/QINGYICODE/RepoPilot)。

## 根因与修复

- 原默认允许列表只有 PetClinic，其他仓库会返回 `REPOSITORY_NOT_ALLOWED`。增加独立的管理接入流程：用户显式授权、GitHub 公开属性与 githubId 核验、持久化授权；模型工具仍绑定原仓库，不能授予权限。
- 原前端等待 20 秒，后端 GitHub 请求最坏约 75 秒。改为 HTTP 202 后台连接任务，进度持久化、刷新恢复、连接/索引分开显示；API 操作总预算 18 秒，最多三次有界尝试。
- 当前环境的代理出口返回 GitHub 403、匿名额度剩余 0；相同目标直连返回 200。未显式指定代理时优先直连，仅网络故障时尝试环境代理；显式代理不旁路。401/404/403/429 不盲目重试，限流保留恢复时间，并约束手动重试。
- 已完成快照复用先于远程元数据读取，避免网络故障影响本机已完成索引。刷新默认分支时保持仓库身份不可替换。

## 已执行检查

`python3 scripts/dev.py mysql-test` 验证本机数据库、固定版本索引、候选与证据边界；新增地址解析、网络路由、限流退避、任务去重、实例租约、私有仓库不授权、身份变化不覆盖、授权撤销拒绝读取、失败索引重试等回归。Vue 类型检查和生产构建通过。

真实 Chromium 浏览器执行 `scripts/connection-smoke.cjs`，接入地址含 `?tab=readme-ov-file`。核验默认分支 SHA、导入 READY、`backend/pom.xml` 文件及 `AgentOrchestrator` 代码检索，刷新后恢复连接任务；1440px 与 390px 无横向溢出、无页面运行时错误。限流按钮禁用使用受控 HTTP 响应，未制造真实 GitHub 限流。

首次真实导入 SHA 为 `4e06ec5fe551998e99cf798aaca629a85b85ce3d`，93 个受支持文件、11 条可达提交、905 条证据。此时旧索引 v2.2 漏掉 `backend/pom.xml` 的模块关系，随后独立修复并升级索引；该问题未当作成功的依赖分析。

索引 v2.3 已在同一 SHA 重新构建，识别出一个 `backend` 服务模块。比较 D1 提交与该版本，识别到 JavaParser、JGit、Validation 三项新增依赖，声明影响服务为 `backend`。直接历史候选工具以 `IMPECCABLE_HOME` 检索，返回真实修复 `bf9c07ff7639c2f8dc779d48eac8fbfb561613fc` 及实际修改依据。没有根 pom.xml 时扫描受支持的子目录 POM；有根 POM 时仍以它的模块声明为边界，不自动混入未声明的目录。

最终本机回归为 54 项单元测试、17 项集成检查通过，4 项外部检查按配置跳过；前端构建通过。Impeccable 检查最初指出状态框单侧粗边框，移除后结果为 `[]`。真实模型另测两次：一次在最终阶段超时，仍保留已验证候选；一次引用辅助检索证据被 `UNVERIFIED_CITATION` 拒绝，工具调用本身均未执行失败。这些失败保留在[脱敏记录](repository-connection-real.json)，不能标记为模型任务全部通过。

## 复现

先运行后端 `python3 scripts/dev.py agent`（无需模型时使用 `backend`）及前端 `npm run dev`，再执行：

```bash
PLAYWRIGHT_MODULE=/tmp/repopilot-browser/node_modules/playwright \
PLAYWRIGHT_BROWSERS_PATH=/tmp/repopilot-browser-binaries \
node scripts/connection-smoke.cjs
```

Playwright 安装方式见 [D5～D8 验收](D5-D8验收.md)。截图、连接任务 ID 和原始运行输出保存在未跟踪的 `.local/connection-*`；仅脱敏验证结果纳入文档。该脚本不调用模型。

授权管理适用于本机单用户工作台，尚未提供公网登录和多租户权限体系。失败恢复有界，不能保证 GitHub 永不故障；不据此声称工具调用失败率达到 4%。
