## 已解决的工程问题

- JGit `toFileHeader` 的合成编辑列表不含完整 hunk 正文：改为解析实际格式化 patch，保存双侧位置，并独立保存纯元数据变更。
- 内容缓存中的回退符号携带旧路径：改为与路径无关的切分结果，文件定位由快照记录绑定；缓存同时保留解析警告。
- 中文查询与 ASCII SHA 列比较引发 MySQL 排序规则错误：仅在输入确为完整 SHA 时执行该列比较，其余走文本索引或字面检索。
- 原始全文 OR 检索会扩大精确符号查询：改为字面优先、无字面命中再全文回退，分页固定检索方式。
- MySQL 连接统一设置 UTC，会校验真实 commit 的存储 epoch 与 JGit 一致。
- 仓库网络支持显式代理，不修改全局代理，也不改变模型客户端配置。

## 实用边界

依赖图以不可变 JSON 保存于 MySQL 的 dependency_graph，查询时加载到应用邻接表。该取舍适合当前单仓库规模，不承诺数据库级大图查询。

当前没有完整 Maven 解析器、外部 BOM 下载、profile 激活、依赖冲突仲裁或运行时服务调用图。测试、provided、optional 和 exclusions 的声明语义有确定性样例覆盖；未知外部版本不补造。任务工作池按单进程设计。

索引已在原型迭代中升级至 v2.2，旧版本保留，查询和比较均显式绑定快照。原始日志、镜像、环境文件与构建产物不纳入 Git；对拟提交文件检查实际凭据，公共结果只保存定位与验证信息。
