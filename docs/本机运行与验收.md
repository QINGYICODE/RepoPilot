# 本机运行与验收

使用完整 JDK 21、Maven 3.9+、Node 22.12+、Python 3 和本机 MySQL 8。数据库连接为 `localhost:3306/repopilot`；不需要 Docker。

## 环境检查

将 `.env.example` 复制为 `.env`，填写本机数据库账户，执行 `scripts/init-local.sql` 建库。Java 安装有多个版本时，先将 `JAVA_HOME` 指向包含 javac 的完整 JDK。检查不会打印密钥，也不会发送模型请求：

```bash
python3 scripts/dev.py doctor
```

doctor 检查 JDK/编译器、Maven、Node、npm、配置是否齐全、前端依赖与 MySQL TCP 端口。端口可连不代表密码、库或迁移有效；这些由下面的数据库集成检查确认。模型配置可暂缺，此时使用 backend 模式。

首次安装前端依赖：

```bash
cd frontend
npm ci --ignore-scripts
```

## 运行

根目录执行 `python3 scripts/dev.py agent`，另一个终端在 frontend 执行 `npm run dev`。暂不配置模型时运行 `python3 scripts/dev.py backend`。默认后端为 `127.0.0.1:8080`、前端为 `127.0.0.1:5173`；健康检查为 `/api/actuator/health`。使用终端 Ctrl+C 正常停止，让任务状态与租约完成收尾。

前往仓库管理输入公开 GitHub 地址，点击接入并授权，等待连接和代码索引均就绪，再返回工作台分析。依赖任务需要不同的两个提交，告警任务可提供部署 SHA；历史任务会恢复当时的版本和脱敏问题。手动选择已经就绪的版本会复用索引。

GitHub Token 只填后端 `GITHUB_TOKEN`；匿名访问耗尽额度时按页面等待时间重试。`REPOSITORY_PROXY` 显式设置后只使用该代理；未设置时直连优先，仅在传输故障时尝试环境代理。Agent 不拥有仓库授权工具。

## 检查与回归

一条命令执行本机 MySQL 集成、后端单元/协议测试、Python 工具回归、前端版本回归、类型检查和生产构建：

```bash
python3 scripts/dev.py check
```

任一步失败立即返回非零退出码。该命令不调用真实模型，也不自动安装依赖。独立检查仍可运行 `mysql-test`、`backend-check`、前端 `npm test` 和 `npm run build`。

固定 50 条回归和真实 Agent 子集见 [评测集说明](../eval/README.md)。`--prepare` 仅为已经授权的仓库补索引；模型评测需要 agent 模式运行和已配置的 LLM。完整真实 PetClinic 业务烟测也可使用 `python3 scripts/dev.py agent-check`。

浏览器检查需要启动前后端和临时 Playwright；安装方法见 [D5～D8 验收](verification/D5-D8验收.md)。`scripts/workspace-smoke.cjs` 不调用模型，验证去重、跨仓库恢复、旧快照链接和手机布局；`connection-smoke.cjs` 验证真实仓库接入；`preview-smoke.cjs` 会调用模型验证业务结果与证据。

测试日志、截图与原始报告保存在被忽略的 `.local`，经核对的报告放在 `docs/verification`。日常运行不需要重新执行固定评测；README 保持项目介绍，开发取舍与尚未完成的验收项写入开发记录。
